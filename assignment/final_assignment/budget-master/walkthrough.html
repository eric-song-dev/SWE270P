2十分钟背景知识Ten minutes of background

读代码之前，先弄清三个概念。TA 的概念题基本都出自这里。

Three ideas to have straight before reading any code. Most concept questions from a TA come from here.

MCP 是什么What MCP is

  • MCP（Model Context Protocol）是一个开放协议，规定了 AI 应用怎样连接外部的工具和数据。消息格式是 JSON-RPC。
  • server 提供能力。我们只用到一种：tool，也就是带名字、说明和参数 schema 的函数。
  • client 连接一个 server，用 tools/list 发现它有哪些工具，用 tools/call 调用。
  • transport 负责传输消息。我们用 stdio：client 把 server 当作子进程启动，双方通过标准输入输出交换消息。另一种标准传输是 Streamable HTTP。
  • server 在处理一次调用的过程中，可以向 client 发 progress notification（进度通知）。
  • MCP (Model Context Protocol) is an open protocol for connecting an AI application to external tools and data. Its messages are JSON-RPC.
  • A server offers capabilities. We use one kind: tools, functions with a name, a description and a schema for their arguments.
  • A client connects to one server, discovers its tools with tools/list and invokes them with tools/call.
  • The transport carries the messages. We use stdio: the client starts the server as a child process and the two exchange messages over standard input and output. The other standard transport is Streamable HTTP.
  • While it handles a call, a server can send the client progress notifications.

LLM 的 function calling 是什么What LLM function calling is

  1. 我们把一组工具定义（名字、说明、参数 schema）连同对话一起发给 LLM。
  2. LLM 可以不回答文字，而是返回 tool_calls：它想调用哪个工具、参数是什么。
  3. 我们的代码执行这次调用，把结果作为一条 tool 消息追加到对话里，再次请求 LLM。
  4. 重复，直到 LLM 返回普通文字。
  1. We send the LLM a list of tool definitions (name, description, argument schema) together with the conversation.
  2. Instead of text, the LLM may answer with tool_calls: which tool it wants to call and with which arguments.
  3. Our code executes the call, appends the result to the conversation as a tool message, and asks the LLM again.
  4. This repeats until the LLM answers with plain text.
为什么这样设计Why it is built this way
MCP 和 function calling 是两段不同的链路，很容易混。LLM 和 agent 之间用的是 function calling（OpenAI 格式）；agent 和工具 server 之间用的是 MCP。agent 站在中间做翻译：它把 MCP 的工具定义转成 function calling 的格式（下面的 to_openai_tool），再把 LLM 发回的 tool_calls 转成 MCP 的 tools/call。
MCP and function calling are two different links, and they are easy to mix up. Between the LLM and an agent we use function calling (the OpenAI format); between an agent and a tool server we use MCP. The agent translates in the middle: it converts MCP tool definitions into the function-calling format (to_openai_tool below) and turns the tool_calls the LLM sends back into MCP tools/call requests.

在这个项目里，agent 指什么What “agent” means in this project

一个 agent 等于三样东西：一段规定角色的 system prompt、一份它被允许使用的工具清单、一个“请求 LLM、执行工具、再请求”的循环。三个 agent 共用同一个循环（AgentRuntime.run_llm），只是提示词、工具和写文件的权限不同。

An agent is three things: a system prompt that fixes its role, the list of tools it may use, and a loop of “ask the LLM, run the tools, ask again”. All three agents share one loop (AgentRuntime.run_llm); they differ in prompt, tools and what they may write.

agent 之间怎么沟通How the agents communicate

  1. 任务交接。orchestrator 调用 agent 的 MCP 工具来派任务，参数就是任务内容。Tester 的失败报告作为 fix_code 的参数交给 Coder；Coder 的说明作为 retest 的参数交回 Tester。
  2. 共享工作区。DESIGN.md、源码和测试都放在同一个项目目录里，而且只通过工具 server 读写。后一个 agent 在前一个的产出上继续工作。
  3. 进度通知。agent 工作时不断向 orchestrator 发 MCP progress notification，界面上的实时日志就是这些通知。
  1. Task hand-offs. The orchestrator assigns a task by calling an MCP tool of an agent, with the task as arguments. The Tester's failure report reaches the Coder as the argument of fix_code; the Coder's notes go back to the Tester as the argument of retest.
  2. A shared workspace. DESIGN.md, the source and the tests sit in one project directory and are read and written only through the tool server. Each agent builds on what the previous one left there.
  3. Progress notifications. While it works, an agent keeps sending MCP progress notifications to the orchestrator; the live log in the UI is made of them.
TA 可能追问A likely follow-up
“agent 之间是直接对话的吗？”不是。agent 之间没有直接连接，所有任务都经过 orchestrator 转交，是一个星形结构。好处是协作顺序完全由代码决定，可预测，也不需要再花 LLM 调用来“商量谁先做”。
“Do the agents talk to each other directly?” No. There is no agent-to-agent connection; every task passes through the orchestrator, a hub-and-spoke layout. The benefit is that the order of collaboration is decided entirely by code: predictable, and no LLM calls are spent on agreeing who goes next.

系统里每一次 LLM 请求都经过 LLMClient.chat()。所以只要在这里计数，就不会漏。

Every LLM request in the system goes through LLMClient.chat(), so counting here misses nothing.

  • temperature 设为 0，让输出尽量稳定。
  • LLM_THINKING 是 DeepSeek 特有的开关。只有在 .env 里配置了才会发送，所以代码对其他 OpenAI 兼容接口也能用。我们设为 disabled，更快也更省 token。

“什么算一次 API 调用？”一次成功返回的 chat completions 请求。record 在请求返回之后才执行，所以抛异常的请求不计数；OpenAI SDK 内部的自动重试也不会被单独计数。如果接口没返回 usage，这次调用仍然计数，token 记为 0。
“What counts as one API call?” One chat-completions request that returned successfully. record runs after the request returns, so a request that raises is not counted, and automatic retries inside the OpenAI SDK are not counted separately. 这是 agent 手里的全部工具。write_file 在第 2 章看过了，这里看另外两处：路径检查和运行测试。

These are all the tools the agents have. write_file appeared in chapter 2; here are two more pieces: the path check and running the tests.

  • resolve 拒绝任何跳出项目目录的路径，LLM 写不到别处去。
  • stdin=subprocess.DEVNULL：这个 server 自己的标准输入就是 MCP 通道，不能让被测代码读到。
  • 60 秒超时：生成的代码万一死循环或在等输入，不会把整个系统卡住。

  • A 60-second timeout: generated code that loops forever or waits for input cannot hang the whole system.

What is MCP, and why does your system use it?MCP 是什么？你们的系统为什么用它？

可以这样回答（英文）A way to answer

MCP, the Model Context Protocol, is an open protocol that standardises how an AI application connects to tools. A server exposes tools; a client lists them and calls them. Because everything speaks the same protocol, each agent and the tool server are separate, replaceable processes.

术语表Glossary

MCP
Model Context Protocol。连接 AI 应用和工具的开放协议。Model Context Protocol. An open protocol that connects AI applications to tools.
MCP server
提供工具的一方。我们有四个：三个 agent 和工具 server。The side that offers tools. We have four: the three agents and the tool server.
MCP client
连接 server 并调用其工具的一方。orchestrator 和三个 agent 都是。The side that connects to a server and calls its tools. The orchestrator and the three agents are clients.
tool
server 暴露的一个函数，有名字、说明和参数 schema。A function a server exposes, with a name, a description and a schema for its arguments.
stdio transport
client 把 server 作为子进程启动，通过标准输入输出传消息。The client starts the server as a child process and exchanges messages over standard input and output.
tools/list, tools/call
MCP 的两种请求：列出工具、调用工具。Two MCP requests: list the tools, call a tool.
progress notification
server 在处理调用期间发给 client 的进度消息。我们的实时日志靠它。A message a server sends the client while handling a call. Our live log is built on it.
function calling
LLM API 的功能：模型返回它想调用的函数和参数，由我们的代码执行。A feature of the LLM API: the model returns the function it wants to call and the arguments, and our code executes it.
agent
角色提示词 + 允许使用的工具 + 调用 LLM 和工具的循环。A role prompt, a set of allowed tools, and a loop that calls the LLM and the tools.
orchestrator
按固定流程给 agent 派任务的代码。不调用 LLM。The code that hands tasks to the agents in a fixed workflow. It makes no LLM calls.
workspace
一次运行的项目目录 generated/run-…/，agent 共享。The project directory of one run, generated/run-…/, shared by the agents.
prompt / completion tokens
发给 LLM 的内容的 token 数 / LLM 写出的内容的 token 数。Tokens in what we send to the LLM / tokens in what the LLM writes.
fix loop
测试失败后 Coder 修复、Tester 复测的循环，最多两轮。The loop of Coder fixing and Tester retesting after a failure, at most two rounds.
smoke test
只检查“能跑起来不报错”的粗粒度测试。我们用它测生成的界面。A coarse test that only checks that something runs without an error. We use it for the generated UI.
AppTest
Streamlit 自带的测试工具，不用浏览器就能运行一个 Streamlit 应用。Streamlit's testing tool, which runs a Streamlit app without a browser.
